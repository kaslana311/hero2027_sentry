# MINCO 重规划热启动边界修复

日期：2026-10-26。工作分支：`codex/point-lio-backend`。

## 1. 本次修什么，不修什么

仅修平滑器生成新轨迹时的起点位置、速度和加速度（PVA）来源。
不修改 MPC 的上一条指令速度预测，不调整控制器速度阈值、速度上限、
ESDF 或避障权重，也不修改 A*、地图、行为树、Point-LIO、底盘物理模型。
不增加机器人运动指令或新的恢复动作。原启动命令、启动参数保持不变。

## 2. 已经观察到的错误链路

旧逻辑满足“旧轨迹未过期、机器人离投影点足够近”，就直接继承旧轨迹
在投影点的 PVA。机器人撞住后，真实速度可以接近零，但旧轨迹仍在
描述一个继续运动的机器人；成功重规划又刷新轨迹缓存时间，错误边界
因此可以一轮轮继承下去，不能只靠缓存的 2 秒有效期自然消除。

本次修改前的 8 秒只读采样中：

- 连续 19 条 MINCO 输出，初始速度模长均约 `0.236230 m/s`，
  初始加速度模长均约 `0.890409 m/s²`。
- 同期真值速度中位数约 `1.46e-7 m/s`；Point-LIO 导航里程计速度
  中位数约 `0.00685 m/s`。两者都说明车辆基本已经停住。

这证明该次现场存在“实际停止、边界仍继承非零运动”的问题。
没有采到截图中切换目标的瞬间，不能把所有 U 形曲线都归结于这一项。

MINCO 把起点速度、加速度当作固定边界，而不是可随意优化掉的软代价。
若边界朝向新目标的反面，多项式在起始时刻就必须向那个方向运动，
之后才能掉头。单纯提高避障权重不能消除这个边界矛盾。

## 3. 修改后的规则

沿用平滑器已有的原始里程计订阅，不从 MPC 取预测速度，也不使用
Nav2 控制器经过速度阈值截断后的反馈。

### 反馈一致性

同一条里程计消息提供位置、姿态、速度和采样时间。位置按消息时间戳
变换到 `map`，`child_frame_id` 下的线速度按同一时刻姿态旋转到 `map`。
TF 查询不等待；失败时跳过该条消息，不能把 `odom` 坐标直接冒充 `map`。
超过 0.5 秒没有有效反馈时，本次平滑返回失败，不伪造静止边界。

### 正常运动仍然热启动

旧轨迹仍须满足原有有效期、投影有效性和距离门限。当它与实际运动
相符时，保留原投影的 **P、V、A 三者**，包括原加速度连续性。
不是每次重规划都归零，也不是新目标一到就强制冷启动。

短暂误差保留原边界；不因一帧噪声、启动时的短暂执行滞后就重置。

### 持续不符时重建边界

新增判断集中在 `WarmStartBoundaryGuard`，初始默认值如下：

| 判断 | 默认条件 |
| --- | --- |
| 有效反馈 | 消息年龄不超过 0.5 秒；不接收明显未来或乱序消息 |
| 确认静止 | 速度不超过 0.03 m/s，且在 2 cm 范围内保持至少 0.5 秒 |
| 静止却仍计划运动 | 投影速度超过 0.10 m/s，或加速度超过 0.50 m/s² |
| 一般速度不符 | 投影与实测的速度向量差超过 0.20 m/s |
| 重建等待 | 上述运动不符持续至少 0.5 秒，按平滑调用时刻判断 |

这些是针对当前采样量级设置的工程门限，不是新发现的机器人物理极限，
也不改变最大速度、最大加速度。3 Hz 重规划时，实际触发还受调用周期量化，
不是承诺精确在某个毫秒触发。

重建时使用实际位置。已确认静止才使用零速度、零加速度；仍在运动时，
使用实际速度，以及速度差分后低通、限幅得到的加速度。
滤波时间常数 0.2 秒，差分加速度按已有 `max_acc` 限幅。
旧投影不存在、超距离或数值无效，也走实际状态边界，而非沿用路径首点。

连续重新生成轨迹不会清空“不符已经持续多久”的记录，避免重复刷新
缓存时间就绕过检查；恢复正常后清除不符记录，正常热启动可继续使用。
反馈中断、生命周期重新配置和明显的仿真时钟回跳会重置相关观测窗口。

## 4. 测试如何证明修改有效

`test/test_warm_start_boundary.cpp` 包含 18 项自动测试：正常巡航、加速、
低速横移的完整 PVA 保留；短暂误差不重置；持续停驶、仅加速度残留、
重复刷新缓存、反向运动不符；反馈异常、时间回跳、噪声和恢复热启动。

其中两项直接调用仓库的 `minco::MINCO_S3NU` 生成五次多项式，
而非只检查布尔判断：

1. 人工设置反向的非零起点速度/加速度，终点在正向。旧边界确实强迫
   轨迹先向负方向运动；确认车辆静止并重建边界后，示例轨迹不再先后退。
2. 当实测车辆确实在反向运动时，同一边界仍保留，不能为了让图形好看
   就把真实速度瞬间归零。

人工回归使用的是现场速度、加速度的量级，不是声称完整重放了当时
的障碍场景或目标切换。没有向运行中的机器人发送测试导航目标。
18 项离线测试通过不等价于全部 Gazebo 脱困场景已验收。

## 5. 效果边界及可能影响

- 判断依赖里程计反馈；如果里程计自身错误地报告运动，不能保证识别真实卡住。
- 从错误旧参考切换到真实边界时，参考 PVA 可能发生一次跳变，这是纠正
  不真实边界的代价；持续确认窗口用于减少误触发，不会承诺绝对无抖动。
- 短暂误差期间仍保留热启动，因此不是“第一次重发目标立刻归零”。
- 真正还在倒退的机器人，轨迹先减速再掉头是合理的；本修复只消除
  与实际运动长期不符的继承，不禁止所有后退轨迹。
- 不改 MPC 速度预测，所以不能据此保证所有脱困都成功；碰撞、感知漏检、
  优化器局部极值等不同原因仍可能导致脱困失败。

Gazebo 验收重点：正常导航连续重规划不出现周期性停车；卡住一段时间后
朝空闲处重发目标，轨迹起点应回到实际车位，且不再无限继承原来的非零
速度和加速度。若仍出现 U 形轨迹，应区分真实运动、边界问题和避障优化结果。
