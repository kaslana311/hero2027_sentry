# 可选局部规划与卡住冷启动（2026-11-04）

适用分支：`codex/point-lio-backend`。本轮不修改仿真仓库、定位、TF、PGM、DOG 滤波、
MPC、MINCO 避障权重/时间权重，也不撤销独立的 ESDF 梯度测试开关。

## 两个启动开关

| 启动参数 | 默认值 | 作用范围 |
| --- | --- | --- |
| `split_local_refinement` | `false` | 仅 `costmap_mode:=split` 且 `field:=rmuc_2027`；静态 A* 后做有边界的局部通道修正 |
| `stuck_cold_start` | `false` | 四种代价地图模式均可；确认运动卡住时，MINCO 暂不继承旧轨迹的 PVA |

二者相互独立。都关闭时保持原来的静态规划/动态平滑和正常热启动。
局部规划开关沿用已存在的启动参数，不新增另一套 planner 或代价地图。
卡住冷启动使用现有 BT 条件节点和已有的后台订阅线程，不新增节点、线程或自定义消息。

主入口运行示例（先启动与 2027 场地相配的仿真，不能使用 2026 场地启动脚本）：

```bash
cd "/home/apocalypse_linux_00/hero2026_-sentry (to_compile_not_develop))"
source /opt/ros/humble/setup.bash
source install/setup.bash

ros2 launch hero_sim_bringup navigation_point_lio_sim.launch.py \
  field:=rmuc_2027 \
  lidar_mode:=dual \
  costmap_mode:=split \
  relay_cmd_vel:=true \
  publish_debug_visualizations:=false \
  point_lio_rviz:=true \
  filter_high_columns:=false \
  high_column_min_z:=0.20 \
  split_local_refinement:=true \
  stuck_cold_start:=true
```

要单独对比一项，只改变对应布尔值，其他参数和起点/目标保持相同。
原有命令没有传入这两项时，均为关闭。主真值入口、Point-LIO 感知入口和后端 shadow
入口也公开该冷启动开关；后端 shadow 入口仍需要原来的先验地图参数，不代表启用后端导航。

## 1. 局部规划具体改了什么

原方法的缺口是：短洞没有双墙拟合约束，局部搜索又不读取内部静态先验墙。
所以只有零散障碍点时，没扫到的真实墙被当作空闲，出现了更短但穿墙的路线。

本轮收紧为：

1. **短洞（模板长度小于 1.5 米）不再做缺乏结构支持的自由软搜索。** 返回原静态路线，
   后续 MINCO 仍照常使用动态代价平滑。不是把短洞从导航中删掉，也不是把动态洞口设为硬障碍。
2. **长洞必须有双侧纵向墙支持。** 仍使用原双墙拟合与有限时间/偏移预算；单侧、零散点或
   拟合失败就退回原路线，而不是猜测缺失墙的位置。
3. **只在匹配成功的有限通道内部允许跨过错位的先验墙。** 双侧墙之间预留机器人半径与
   半格栅格余量，防止从感知缺口侧穿墙；通道前后保留端部余量，避免被先验膨胀端帽卡住。
4. **通道外恢复先验墙约束。** 读取先验代价图的独立快照，不写地图；只有原先已接受静态
   路径的窄栅格带可保留原有起点接回段。原来的 A* 起点恢复代码未改。
5. **洞口动态占据仍是软代价。** 双墙约束的是通道侧边，不是所有动态占据格；横跨通道的
   未滤洞顶仍可被软规划穿过。此设计也意味着真正的横向实体障碍仍没有硬安全保证。
6. 输出点位不额外移动，但用约 15 厘米弧长邻域的弦方向估计朝向，减少八邻接搜索在
   0°/45°之间交替给 MINCO 路径预处理带来的锯齿朝向。首尾与回接姿态仍保留原路径值。

这不是保证所有洞、所有定位漂移都能通过的全局重定位方法。模板、双墙识别、当前动态地图
以及静态先验本身仍会影响结果。尤其本轮对短洞优先保守回退，**没有声称把短洞抗漂移能力
提高到 50 厘米**。已有长洞测试覆盖 50/60/70 厘米、两个正交方向和正反向通行。

查看局部规划状态：

```bash
ros2 topic echo /red_standard_robot1/GridBased/refinement_status
```

例如 `applied`、`short_tunnel_static_fallback`、`no_supported_wall_pair`、
`outside_tunnel_regions`、`budget_exhausted`。回退不是让导航失败，而是继续使用原静态路线。
可在启用该启动参数后动态停用局部修正：

```bash
ros2 param set /red_standard_robot1/planner_server GridBased.local_refinement_enabled false
```

如果启动时从未启用局部修正，就没有加载区域模板；需要重新启动并传 `true`，不能只在运行中
把布尔量改为 `true` 就得到完整配置。

## 2. 卡住时怎样改变热启动

接口为：

```text
现有 IsStuckCondition 的运动卡住检测
    → navigation/motion_stalled（std_msgs/Bool）
    → MINCO 的可选订阅与旧轨迹失效标记
```

开启时，启动工厂仅为现有 BT XML 生成一份临时副本，为唯一的 `IsStuckCondition` 加上
一个输出话题端口，并向 MINCO 注入同名输入话题和 1 秒接收超时。
原 XML、节点顺序、恢复次数、清图动作和倒车参数均不改变；关闭时不生成这份副本。

判定复用既有数值：平移指令速度至少 `0.08 m/s`，持续约 `1.5 s`，里程计位移不足
`0.03 m`，且两类输入在 `0.5 s` 新鲜度内。检测在既有后台回调里运行，**不需要等 BT
进入恢复子树后才通知平滑器**。

- 收到新的确认卡住事件：旧缓存轨迹失效。新的平滑请求以原输入路径首点为位置、零速度和
  零加速度为边界，不沿着旧轨迹的撞墙速度继续继承。
- 卡住期间：即使取消导航产生零指令，也不立即重新开启热启动。
- 里程计从卡住锚点实际变化至少 3 厘米：释放禁止状态，恢复对**卡住后新生成轨迹**的正常
  投影继承。不会重新捡起卡住之前的旧 PVA。
- 正负事件恰好都发生在两次平滑之间：事件序号仍使旧缓存失效一次。
- 新事件在继承旧轨迹的优化过程中到达：丢弃尚未发布的热启动候选，让既有重试生成冷候选。
  这种竞态下可能多一次平滑重试/原有清图动作，不新增另一套恢复状态机。
- 接收状态超过 1 秒没有更新：停止持续禁止，避免发布者退出后永久无法热启动；已经失效的
  卡住前旧缓存不会因此复活。再次收到确认卡住时仍按新一轮处理。

**没有把实测速度、真值速度或位置误差接入 PVA 重建/速度闭环。** 里程计位置仅被已有 BT
检测器用于离散的“是否卡住”，正常时仍继承 MINCO 自己旧轨迹的投影速度/加速度。
单纯代价图 253/254 重叠不发布运动卡住真值，避免未滤洞口导致正常热启动被误关。
原来的代价重叠 BT 恢复触发仍保留，没有被本轮删掉。

查看实时信号：

```bash
ros2 topic echo /red_standard_robot1/navigation/motion_stalled
```

此机制不保证物理上被顶住的车一定脱困，也无法在里程计本身持续漂移时可靠区分真实位移。
它解决的是确认卡住后仍继承旧轨迹边界的问题；实际脱困仍由既有控制、倒车恢复与物理模型决定。
本轮未给这个跨 BT/平滑器的连接提供运行中切换，使用启动布尔量避免半连接状态。

## 3. 验证与未验证内容

- 13 组原生局部规划回归（其中横向错位 sweep 内含 24 个场景）：保留静态墙的长洞过洞、
  双向/旋转、侧墙缺口、软洞口、短洞回退、通道外先验障碍、方向估计、预算/输入保护等。
- 225 项 Python 启动/模式/配置与原生回归：默认模式旧参数快照不变，开启冷启动仅新增
  一个 BT 端口和两个 MINCO 参数，两个开关保持独立。
- 17 个 C++ 测试：包括此前 8 个 ESDF 开关回归、5 个状态门控单元测试、4 个真实 BT 条件
  节点加真实 MINCO 的隔离集成测试。实测零 twist 的移动输入仍正常热启动；卡住后多项式
  起点 V/A 为零；移动后恢复；第二次卡住可重触发；成本重叠本身不关热启动。
- 3 个真实 Nav2 规划回归：60 厘米错位的长洞修正及开关、先验地图不变、原 A* 起点恢复。
- 此前 PGM 的缺失感知反例重新检查：只给一个无关点，旧实验路线原本从 3.504 米抄成
  1.434 米穿墙；本轮启用/禁用均为 3.504 米且点位相同，不再生成该盲区捷径。

测试使用隔离 ROS 域、人工地图/位移输入，不发真实底盘速度。没有声称重现了之前罕见的
“空地左右晃”完整现场，也没有声称已经完成 Gazebo 六洞通行率或碰撞脱困的实测验收。
详细测试代码与日志在本分支对应的 `local_research/2026-11-04_navigation_improvements/`，
按既有本地排除规则保存、不跟踪。

## 4. 2026-11-06 基线归档与已知问题

按用户要求，在原 `codex/point-lio-backend` 分支归档上述局部修正、可选卡住冷启动、
独立 ESDF 梯度开关及其测试；之后才从已提交基线创建单雷达实验分支。
保留当前默认关闭的两个启动开关；本次归档不顺带改变权重、地图、TF、传感器或速度上限。

2026-11-05 后续现场使用 `map_odom_offset_y=0.3`，用户报告长洞漏扫墙体处通行异常。
补录 433.750–467.918 仿真秒的 219 次规划全为 `outside_tunnel_regions`，静态与局部
输出点位相同；MINCO 曲线仍能进入“静态有墙、动态为空闲”的格子。更早日志也出现过
双墙不足和端点校验失败后的回退。**本次提交仅归档现有实验能力，并未修复这项新发现，
不能据理想双墙回归声称真实稀疏感知条件下已经稳定抗漂移。**

当前拟合侧墙只约束局部搜索，尚未贯通到后续 MINCO；匹配/选区失败后返回原静态路线，
动态地图又不区分漏扫和确认自由。因此这仍是后续需要解决的规划—平滑接口缺口。
洞口动态占据仍保持软代价，不在归档时暗中改成硬障碍。
